## Overview

This report measures, on Amazon Bedrock, how many tokens, how much cost and how many LLM requests each model needs for an AI coding agent to finish the same backend implementation task.

A **Ralph loop** gives the same prompt to a fresh agent session over and over. Only the repository (files and git history) carries over between iterations; the conversation does not. The agent therefore has to read the repository each time, work out what is left, and create a completion marker file when it judges the task done. The harness grades the result with the official tests after every iteration.

The models compared are frontier models callable on Amazon Bedrock (group 1) and Chinese open-weight models callable on Amazon Bedrock (group 2). Open-weight means the trained weights are published. The reference report ran each model with a different agent harness and provider API; this report ran every model with the same harness (pi coding agent) and the same API (Bedrock Converse), so the differences shown are differences between models under one set of conditions.

- **Cost** [calculated: reported tokens × Bedrock US cross-Region inference prices as of 2026-10-12, median per run]
  - Lowest: GPT-6 Luna $0.027 and Claude Haiku 5.5 $0.065
  - Highest: GPT-6 Astra $3.495, Claude Fable 5.1 $2.566 and Claude Opus 4.8 $2.018

## Notation

This report labels values by their nature.

- **[fact]**: Observed directly by running or querying something, with the time of observation.
- **[calculated]**: Derived by a fixed rule, such as reported token counts multiplied by published prices. Not a billed amount.
- **[estimate]**: Involves an assumption, which is stated.
- **[source]**: The material a number or judgment rests on.

Values that cannot be confirmed from the material are not invented; they are marked "not verifiable" or "n/a".

## Reference Benchmark and Task

### Task and completion criteria [source: the reference report, PROMPT-en.md and harness scripts in its repository]

Every model receives the same task: implement the [RealWorld](https://realworld-docs.netlify.app/specifications/backend/endpoints/) backend API with TypeScript, Fastify, Prisma and SQLite. The scope covers JWT authentication, users and profiles, article CRUD, comments, favorites, tags and feeds.

A run counts as completed only if both conditions hold:

1. The agent verifies the completion conditions itself and creates a `.ralph-done` file at the repository root.
2. The harness grader re-runs the official RealWorld Hurl API tests (13 files, 154 requests) and all 13 files pass. Hurl is a test tool that runs HTTP requests and expected responses written in plain text files.

If `.ralph-done` exists but grading does not pass all 13 files, the harness deletes the file and starts the next iteration.

### Safeguards

The reference harness has three safeguards, and this report used the same values.

- **Stall watchdog**: ends a session when none of the session transcript, logs or repository files change for 300 seconds.
- **Run time cap**: ends a run that exceeds 20 minutes (1,200 seconds).
- **Cost guard**: stops a run when the running cost estimate exceeds the configured limit.

### Metrics in the reference report [fact: reference page data, checked 2026-10-12 15:40 UTC]

For each condition (model × harness), the reference report gives per-run elapsed time, commit count, output tokens, cost at each provider's public list prices, completion and iteration count. It has 28 conditions, 19 models and 117 runs, all completed. Because its costs are not Bedrock prices, this report re-priced the published token counts of the same models at Bedrock prices for comparison.

### Claude Fable 5.1 and data retention

When first checked, Bedrock rejected Claude Fable 5.1 with `data retention mode 'default' is not available for this model` [fact]. According to the [Data retention page of the Bedrock User Guide](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html) (checked 2026-10-13), Claude Fable 5 and 5.1 can be called only when the account's effective data retention mode is `aws_review` or higher [source]. The setting is per account and per Region and cannot be changed with a request parameter.

After the account owner changed the us-east-1 data retention mode from `inherit` to `aws_review` (2026-10-13 04:25:43 UTC), the new value was confirmed with the query API and a short request succeeded; then the five runs were executed [fact]. The setting behaves as follows [source: same page].

- It is set through the API, without a console page. Example: `aws bedrock put-account-data-retention --region us-east-1 --mode aws_review`. Setting `--mode inherit` reverts it.
- It applies to every bedrock-runtime request the account sends in that Region.
- Prompts and outputs of Fable 5 and 5.1 requests are retained inside the AWS boundary for up to 30 days and may be reviewed by AWS staff. They are not shared with the model provider.
- Other models follow the modes they allow. For example, requests to a model that allows no retention (`none`) are not retained even with this setting on.
- With cross-Region inference, retained data is stored in the Region that actually served the request.

Because this changes a data retention policy, anyone repeating the experiment needs the account owner to review this impact and decide.

## Test Configuration

### Agent harness [fact]

- Every model used [pi coding agent](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) 0.87.1, the same version as the reference report's pi conditions.
- Calls went through the Bedrock Converse API with thinking set to medium. Claude models receive adaptive thinking with effort=medium; for other models pi sends no reasoning field, so the model default applies.
- One difference from the reference report: pi 0.87.1 has no settings for Claude Haiku 5.5, so Bedrock rejected its requests. `haiku-5` was added to two model-name lists in the pi bundle (adaptive thinking and prompt caching). Requests to other models are unaffected.

### Multi-agent setup

The reference report runs a single agent and does not define a multi-agent setup. This report used the following one: two agents on the same model, run one after the other within each iteration, exchanging information through files in the repository.

1. **Builder**: receives the reference `PROMPT-en.md` unchanged and implements the task. From the second iteration on, one sentence is appended telling it that a verification agent reviewed the previous iteration and that it should read REVIEW.md first. Only the builder may create `.ralph-done`.
2. **Verifier**: receives a verification prompt in a fresh session, starts the server, runs the official Hurl tests itself and writes a verdict (PASS/FAIL), failing items, causes and a fix list to `REVIEW.md`. It does not modify other files.
3. **Grading**: a grader with the reference report's criteria decides completion.

### Isolation and credentials [fact]

- Every agent session and every grading pass ran in its own Docker container built from Amazon Linux 2023, Node 22.23.3, pi 0.87.1 and hurl 8.0.1.
- Each container was limited to 8 GB of memory, 4 CPUs and 4,096 processes, and mounted only that run's repository, session records and home directory.
- No AWS access keys entered the containers. They received only a Bedrock short-term API key, usable only for Bedrock calls and expiring within an hour, re-issued every 10 minutes.

### Safeguards and scheduling [fact]

- Up to 30 iterations per run, a 1,200-second run time cap and a 300-second stall watchdog.
- Cost limits of $100 per run, $500 per model and $7,000 overall.
- The 13 models ran with up to seven models in parallel; each model's five runs were sequential. Claude Fable 5.1 ran alone after all other models had finished.
- English prompts only.

### Metric definitions

- **Completed**: a run that passed official grading. Medians and min/max use completed runs only.
- **Tokens** [fact]: the usage Bedrock reported with each response, summed over all builder and verifier requests. Input means uncached input tokens; output includes reasoning tokens; cache reads and cache writes are counted separately.
- **Cost** [calculated]: token counts multiplied by the prices under "Prices Applied". Cache writes use the 5-minute cache price, because pi does not set a cache duration and Bedrock defaults to 5 minutes.
- **Ralph iterations**: the number of iterations in which the builder ran, the same definition as the reference report's iteration count.
- **LLM requests**: the number of responses the model returned, the model-level "turns", builder and verifier combined.
- **Run time**: from the start to the end of a run, including both sessions and grading. The reference report's elapsed time is the agent session time, a different definition.

### Interpretation

**Between groups.**

The Chinese open-weight models sent more LLM requests (about 1.5× by group value), produced more output tokens (about 2.3×) and took longer (about 1.4×) to finish the same task. Their Bedrock prices were not low either.

- Kimi K3's input/output prices ($3.3/$16.5 per million tokens) are higher than those of Claude Sonnet 5.5 and GPT-6.1 Sol ($2.2/$11).
- GLM 5.3 has a low output price ($5.808), but its cache-read price ($0.3432) is about 3× Sonnet 5.5's ($0.11) and it read many cached tokens (median 3,612,806). About 68% of its run cost came from cache reads. [calculated: median cache-read tokens × price divided by median run cost]

As a result its cost per run was about 2.0× the frontier group value. Two caveats apply:

- The comparison uses Bedrock prices. The cost of self-hosting the open-weight models is not covered.
- Group 2 contains only 2 models, so its group value is weak evidence.

**Between models (frontier).**

- **Price is the main driver of cost differences.**
  - GPT-6 Luna and Claude Haiku 5.5 cost $0.11/$0.55 for input/output. They used 1,057,982 and 2,156,808 total tokens, yet cost only $0.027 and $0.065 per run.
  - GPT-6 Astra and Claude Fable 5.1 have the highest input/output prices ($11/$55). Cache reads cost $1.1 for GPT-6 Astra and $0.275 for Fable 5.1. Per run, GPT-6 Astra cost $3.495 and Fable 5.1 $2.566, so GPT-6 Astra was the more expensive of the two. Output tokens were 22,221 and 26,693; cache-read tokens were 1,236,901 and 1,096,620.
- **Within one price tier, usage differences show.**
  - Claude Sonnet 5 and Sonnet 5.5 share input/output prices ($2.2/$11); only Sonnet 5's cache-read price is twice as high ($0.22).
  - Sonnet 5 sent 85 LLM requests and used 3,059,198 total tokens for $1.179. Sonnet 5.5 sent 25 requests and used 445,388 tokens for $0.306, so Sonnet 5 cost about 3.9× as much.
  - The gap between Claude Opus 5.5 ($0.907) and Opus 4.8 ($2.018) combines price (input/output $4.4/$22 vs $5.5/$27.5, cache read $0.22 vs $0.55) and usage (35 vs 60 requests).
- **Speed**: GPT-6 Sol was both the fastest (3.1 minutes per run) and the model with the fewest output tokens (8,544).

**Variation across the five runs.** For 12 models the most expensive run cost at most 1.35× the median. The exceptions:

- Claude Opus 5: run 3 used 91 LLM requests, 3,851,983 total tokens and 1 iteration, costing $3.726 (about 1.9× the median).
- GPT-6 Luna: run 3 used 113 LLM requests, 1,979,669 total tokens and 3 iterations, costing $0.066 (about 2.5× the median).

**Cost and effect of the multi-agent setup.**

- The verifier's median cost was about 4% (GLM 5.3) to 25% (GPT-6 Luna) of the median run cost. [calculated: ratio of per-model medians]
- Because most runs finished in one Ralph iteration, the builder actually read the verifier's REVIEW.md only in the 4 runs with two or more iterations.
- Of the 69 iterations that passed the official grader, the verifier also said PASS in 62.
  - In 5, the server listened on port 8000 instead of the `PORT` environment variable, so the verifier reported FAIL (Claude Sonnet 5.5 2, GPT-6 Luna 1 and GPT-5.6 Sol 2).
  - In 2, the verifier session terminated itself and left no verdict.
  - No iteration had a verifier PASS while the official grader failed to pass all 13 files.
- There is no control group without a verifier, so the verifier's effect on completion or cost cannot be quantified (not verifiable).

**Comparison with published runs of the same model.**

- Claude Opus 5.5, Claude Sonnet 5.5, Claude Haiku 5.5 and GPT-6 Sol stayed within ±10% of the re-priced published runs even with the verifier added, because the builder's cost alone was 0.86–0.95× the published runs.
- GPT-6.1 Sol produced 20,621 output tokens against 13,251 in the published runs, and cost about 1.6× as much.
- Kimi K3 produced 39,505 output tokens against 18,667 in the published runs, and cost about 1.9× as much.
- Which endpoint the published runs used (Bedrock or the provider's API) was not verified.
- GLM 5.3's published baseline ($0.544) is an [estimate] that borrows glm-5.3-flash's tokens. The measured GLM 5.3 produced 59,582 output tokens, about 2.6× that baseline, and cost $1.821, about 3.3×.

**Incomplete runs and anomalies.**

- **1 run(s) did not complete.**
  - GLM 5.3 run 4: In iteration 1 the builder started a node test server in the foreground and hung; the 300-second stall watchdog ended the session. Iteration 2 hit the 20-minute run cap before the builder created `.ralph-done`. Grading right after the cap passed all 13 files, but under the completion rule (`.ralph-done` plus 13 passing files) the run counts as incomplete.
- **Stall watchdog**: GPT-6 Luna run 3. In iteration 1 the builder ran `npm run dev` in the foreground and the session hung until the 300-second stall watchdog ended it. After iteration 2 the grader passed 5 of 13 files; the run completed in iteration 3.
- **3 sessions terminated themselves** by killing their own process (Claude Sonnet 5.5 builder, Claude Opus 4.8 verifier and GLM 5.3 verifier). Only Claude Sonnet 5.5 run 5 needed an extra iteration as a result.
- **Transient Bedrock stream errors** ("Bedrock stream ended without a stop reason") occurred (Kimi K3 run 3, 2×). pi retried automatically and completion was not affected.

## Limitations

1. **One task, five runs per model.** Rankings are observations for this task and this setup. Even within one model, the most expensive run cost up to about 2.7× the cheapest (GPT-6 Luna).
2. **The setup differs from the reference report.** The reference report ran a single agent per model with different harnesses (Claude Code, Codex CLI, pi and others). Here every model ran on pi and Bedrock Converse with a builder plus a verifier, so tokens and cost include the verifier's share. This compares models within one harness, not harnesses.
3. **The first attempt was discarded.** The first attempt ran up to seven agents directly on one host without containers. Session records showed agents running host-wide commands such as `pkill -f` and `fuser -k`, which could stop other runs' servers or the grader's server. Because contamination could not be ruled out, those results were dropped and the runs repeated in isolated containers. The reference report runs one run at a time and does not have this problem.
4. **The verifier checked the server port more strictly than the original criteria.** The verifier prompt asks the server to listen on the `PORT` environment variable, which the original completion criteria do not require. The official grader finds the port the server actually opened, so this changes only the content of REVIEW.md, not completion.
5. **Some sessions killed their own process (exit 143).** pi receives the whole prompt as a command-line argument, as in the reference report. When an agent runs `pkill -f` with a phrase from its prompt or kills all node processes, it kills itself as well. The verifier's exposure comes from phrases such as `npm run dev` in this report's verifier prompt. The prompts were not changed mid-experiment so that finished runs stayed comparable.
6. **The verifier's effect cannot be judged.** There is no control group without a verifier, and most runs completed in the first iteration, so few builders actually read REVIEW.md.
7. **Group 2 has only 2 models.** GLM 5.3 is not in the reference report, so its published baseline is an [estimate] borrowing glm-5.3-flash's tokens.
8. **Kimi K3's caching differed from its model card.** The card says explicit prompt caching is offered only through APIs other than Converse, yet Bedrock reported cache-read and cache-write tokens for Converse calls. Costs use the reported values; how caching was applied could not be verified.
9. **Timing and concurrency differ.** Claude Fable 5.1 ran alone, about 4 h 18 min after the other 13 models had finished. Bedrock load and the number of concurrent runs on the host may have differed; the effect on run time was not measured. Tokens and cost are assumed to depend less on timing, but this was not verified [estimate].
10. **Costs are calculated.** They use 2026-10-12 prices and change when prices change.
