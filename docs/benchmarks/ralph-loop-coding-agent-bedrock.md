## 개요

이 보고서는 AI 코딩 에이전트가 같은 백엔드 구현 과제를 끝까지 완성하는 데 모델마다 토큰, 비용, LLM 요청이 얼마나 드는지를 Amazon Bedrock에서 직접 측정한 결과입니다.

**랄프 루프(Ralph loop)** 는 같은 프롬프트를 새 에이전트 세션에 반복해서 주는 실행 방식입니다. 반복과 반복 사이에는 저장소(파일과 git 이력)만 남고 대화 기록은 이어지지 않습니다. 그래서 에이전트는 매번 저장소를 읽고 남은 작업을 스스로 찾아야 하며, 과제를 끝냈다고 판단하면 완료 표시 파일을 만듭니다. 하네스는 반복이 끝날 때마다 공식 테스트로 결과를 채점합니다.

비교 대상은 Amazon Bedrock에서 호출할 수 있는 프론티어 모델(그룹 1)과 중국 오픈웨이트 모델(그룹 2)입니다. 오픈웨이트 모델은 학습된 가중치가 공개된 모델을 말합니다. 원 리포트는 모델마다 다른 에이전트 하네스와 제공사 API로 실행했지만, 이 보고서는 모든 모델을 같은 하네스(pi coding agent)와 같은 API(Bedrock Converse)로 실행했습니다. 그래서 여기서 보이는 차이는 같은 실행 조건에서의 모델 간 차이입니다.

## 요약

- **실측 범위** [사실]
  - Amazon Bedrock us-east-1에서 14개 모델을 랄프 루프로 5회씩, 모두 70개 run을 실행했습니다.
  - 13개 모델은 2026-10-12 22:28 ~ 2026-10-13 00:18 UTC에 실행했습니다. Claude Fable 5.1은 계정의 Bedrock 데이터 보존 모드를 바꾼 뒤 2026-10-13 04:36 ~ 05:21 UTC에 따로 실행했습니다.
  - 구성은 같은 모델로 만든 빌더·검증자 2-에이전트입니다.
  - 그룹 1(Bedrock에서 호출할 수 있는 프론티어 모델) 12개, 그룹 2(Bedrock에서 호출할 수 있는 중국 오픈웨이트 모델) 2개입니다.
- **완주** [사실]
  - 70개 run 중 69개가 공식 채점을 통과했습니다. 공식 채점은 RealWorld Hurl 테스트 13개 파일(요청 154개)이 모두 통과해야 합니다.
  - 13개 모델이 5회 모두 완주했고, 나머지는 GLM 5.3 4/5입니다.
  - 모든 모델의 랄프 반복 중앙값은 1회입니다. 완주한 run 중 반복이 2회 이상 필요했던 run은 3개입니다.
- **비용** [계산: 보고된 토큰 × 2026-10-12 기준 Bedrock US 교차 리전 추론 단가, run 1회 중앙값]
  - 가장 낮은 모델: GPT-6 Luna $0.027, Claude Haiku 5.5 $0.065
  - 가장 높은 모델: GPT-6 Astra $3.495, Claude Fable 5.1 $2.566, Claude Opus 4.8 $2.018
  - 최고와 최저의 차이는 약 130배입니다.
- **그룹 비교** [계산]
  - 중국 오픈웨이트 2개 모델(Kimi K3 $1.422, GLM 5.3 $1.821)은 그룹 대표값(모델별 중앙값의 중앙값) $1.621로, 프론티어 그룹 대표값($0.831)의 약 2.0배였습니다.
  - 출력 토큰은 약 2.3배, 전체 토큰은 약 2.3배, LLM 요청은 약 1.5배 많았습니다.
  - 그러나 프론티어 그룹 안의 비용 차이(약 130배)가 그룹 간 차이보다 훨씬 큽니다. 두 모델의 비용 순위는 14개 중 9위와 10위(낮은 순)이고, Claude Opus 5, Claude Opus 4.8, Claude Fable 5.1, GPT-6 Astra보다는 저렴했습니다.
  - 따라서 비용은 그룹 단위가 아니라 모델 단위로 판단해야 합니다.
- **비용을 좌우한 요인** [계산]
  - 완주한 run의 전체 토큰 중 94%가 캐시 읽기였습니다. 캐시 읽기는 앞선 요청에서 저장해 둔 프롬프트 앞부분을 다시 읽은 토큰으로, 일반 입력보다 단가가 낮습니다.
  - 그래서 출력 단가만이 아니라 캐시 읽기 단가와 사용량이 비용을 크게 좌우했습니다. 예를 들어 GLM 5.3은 run 비용의 약 68%가 캐시 읽기에서 나왔습니다.
- **Claude Fable 5.1** [사실·계산]
  - 계정의 us-east-1 데이터 보존 모드를 `inherit`에서 `aws_review`로 바꾼 뒤 호출할 수 있었고, 5회 중 5회 완주했습니다.
  - run당 비용 중앙값은 $2.566로 14개 중 13위(낮은 순)입니다. 입력·출력 단가($11/$55)는 GPT-6 Astra와 같고 Claude 모델 중 가장 높습니다.
  - `aws_review` 모드에서는 Fable 5·5.1 요청의 프롬프트와 출력이 AWS 경계 안에 최대 30일 보관되고, AWS가 사람 검토를 할 수 있습니다. 모델 제공사와는 공유되지 않습니다.
- **공개 벤치마크와의 비교** [계산]
  - 원 리포트가 같은 pi 하네스로 실행한 6개 모델의 공개 run을 Bedrock 단가로 환산해 이번 실측과 비교했습니다.
  - 4개 모델(Claude Opus 5.5, Claude Sonnet 5.5, Claude Haiku 5.5, GPT-6 Sol)은 이번 실측(검증자 포함)과 ±10% 안에서 일치했습니다.
  - 반면 GPT-6.1 Sol 약 1.6배, Kimi K3 약 1.9배로 더 높게 나왔습니다.
- **총 실행 비용** [계산]
  - 집계에 쓴 실행 $88.42(Claude Fable 5.1 $12.87 포함), 폐기한 1차 실행 $17.60, 합계 $106.02입니다.
  - 모델별 사용액이 가장 큰 GPT-6 Astra도 $16.82로, 모델당 한도 $500 안에서 끝났습니다. 실제 청구액은 AWS Cost Explorer에서 확인해야 합니다.

## 참고 벤치마크와 과제

### 과제와 완주 기준 [출처: 원 리포트와 저장소의 PROMPT-en.md, 하네스 스크립트]

모든 모델이 같은 과제를 받습니다. 과제는 [RealWorld](https://realworld-docs.netlify.app/specifications/backend/endpoints/) 백엔드 API를 TypeScript, Fastify, Prisma, SQLite로 구현하는 것입니다. 범위는 JWT 인증, 사용자와 프로필, 글 CRUD, 댓글, 즐겨찾기, 태그, 피드입니다.

완주로 인정되려면 두 조건을 모두 만족해야 합니다.

1. 에이전트가 완료 조건을 직접 확인한 뒤 저장소 루트에 `.ralph-done` 파일을 만듭니다.
2. 하네스의 채점기가 공식 RealWorld Hurl API 테스트(13개 파일, 요청 154개)를 다시 실행했을 때 13개 파일이 모두 통과합니다. Hurl은 HTTP 요청과 기대 응답을 텍스트 파일로 적어 실행하는 테스트 도구입니다.

`.ralph-done`이 있어도 채점에서 13개 파일을 모두 통과하지 못하면, 하네스가 그 파일을 지우고 다음 반복을 진행합니다.

### 안전장치

원 리포트의 하네스에는 세 가지 안전장치가 있고, 이 보고서도 같은 값을 썼습니다.

- **멈춤 감지**: 세션 기록, 로그, 저장소 파일 중 어느 것도 300초 동안 바뀌지 않으면 세션을 종료합니다.
- **run 시간 상한**: run 하나가 20분(1,200초)을 넘으면 종료합니다.
- **비용 가드**: 실행 중 비용 추정치가 정해진 한도를 넘으면 run을 멈춥니다.

### 원 리포트의 지표 [사실: 원 리포트 페이지 데이터, 2026-10-12 15:40 UTC 확인]

원 리포트는 조건(모델 × 하네스)별로 run마다 소요 시간, 커밋 수, 출력 토큰, 각 제공사의 공개 API 정가로 계산한 비용, 완주 여부, 반복 횟수를 보고합니다. 원 리포트에는 28개 조건, 19개 모델, 117개 run이 있고 모두 완주했습니다. 원 리포트의 비용은 Bedrock 단가가 아니므로, 이 보고서는 같은 모델의 공개 run 토큰을 Bedrock 단가로 다시 계산해 비교했습니다.

## 비교 대상 모델

### 분류와 Bedrock 호출 가능 여부 [사실: 2026-10-12 확인]

호출 가능 여부는 세 단계로 확인했습니다. 첫째, Bedrock 사용자 가이드의 모델 카드와 리전별 제공 표를 확인했습니다. 대상 모델은 모두 us-east-1에서 리전 내 엔드포인트로는 제공되지 않고, 미국 지역 교차 리전 추론 프로필(`us.`로 시작하는 모델 ID)로 호출합니다. 둘째, 실행 계정에서 읽기 전용 역할로 대상 모델의 약관 동의, 권한, 사용 자격, 리전 제공 상태를 조회했습니다. 셋째, 모델마다 짧은 프롬프트를 실제로 보내 응답을 확인했습니다.

Kimi K3와 GLM 5.3의 Bedrock 모델 카드는 두 모델을 각각 "open-weight model", "open weight text generation model"이라고 적고 있습니다 [출처]. GLM 5.3은 원 리포트에 없는 모델입니다. 원 리포트의 glm-5.3-flash가 Bedrock에서 제공되지 않아, 같은 계열 중 Bedrock에서 제공되는 GLM 5.3을 별도로 추가했습니다.

### Claude Fable 5.1과 데이터 보존

Claude Fable 5.1은 처음 확인할 때 Bedrock이 `data retention mode 'default' is not available for this model` 오류로 호출을 거부했습니다 [사실]. [Bedrock 사용자 가이드의 Data retention 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html)(2026-10-13 확인)에 따르면, Claude Fable 5와 5.1은 계정의 유효 데이터 보존 모드가 `aws_review` 이상이어야 호출할 수 있습니다 [출처]. 이 설정은 리전별 계정 단위 구성이며, 요청 파라미터로는 바꿀 수 없습니다.

계정 소유자가 us-east-1의 데이터 보존 모드를 `inherit`에서 `aws_review`로 바꾼 뒤(2026-10-13 04:25:43 UTC), 조회 API로 바뀐 값을 확인하고 짧은 요청이 정상 응답하는 것을 확인한 다음 5회 실행했습니다 [사실]. 이 설정은 다음과 같이 동작합니다 [출처: 같은 문서].

- 콘솔 화면 없이 API로 설정합니다. 예: `aws bedrock put-account-data-retention --region us-east-1 --mode aws_review`. 되돌릴 때는 `--mode inherit`로 다시 설정합니다.
- 이 계정이 해당 리전에서 보내는 모든 bedrock-runtime 요청에 적용됩니다.
- Fable 5·5.1 요청의 프롬프트와 출력은 AWS 경계 안에 최대 30일 보관되고, AWS가 사람 검토를 할 수 있습니다. 모델 제공사와는 공유되지 않습니다.
- 다른 모델은 각 모델이 허용하는 모드를 따릅니다. 예를 들어 보관 안 함(`none`)을 허용하는 모델의 요청은 이 설정을 켜도 보관되지 않습니다.
- 교차 리전 추론으로 호출하면 보관 데이터는 요청이 실제로 처리된 리전에 저장됩니다.

데이터 보존 정책을 바꾸는 일이므로, 같은 실험을 하려면 계정 소유자가 이 영향을 확인하고 결정해야 합니다.

## 실행 구성

### 에이전트 하네스 [사실]

- 원 리포트의 pi 조건과 같은 [pi coding agent](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) 0.87.1을 모든 모델에 썼습니다.
- Bedrock Converse API로 호출했고, 사고(thinking) 설정은 medium입니다. Claude 모델에는 adaptive thinking과 effort=medium으로 전달됩니다. Claude가 아닌 모델에는 pi가 reasoning 필드를 보내지 않으므로 모델 기본값이 적용됩니다.
- 원 리포트와 다른 점이 하나 있습니다. pi 0.87.1에는 Claude Haiku 5.5용 설정이 없어 Bedrock이 요청을 거부하므로, pi 번들 안의 모델 이름 목록 두 곳(adaptive thinking, 프롬프트 캐싱)에 `haiku-5`를 추가했습니다. 다른 모델의 요청에는 영향이 없습니다.

### 멀티 에이전트 구성

원 리포트는 에이전트 하나로 실행하고 멀티 에이전트 구성을 정의하지 않습니다. 이 보고서는 다음 구성을 정했습니다. 에이전트는 2개이고 둘 다 같은 모델이며, 한 반복 안에서 아래 순서로 차례로 실행됩니다. 에이전트끼리는 저장소의 파일로 정보를 주고받습니다.

1. **빌더**: 원 리포트의 `PROMPT-en.md`를 그대로 받아 구현합니다. 두 번째 반복부터는 "검증 에이전트가 이전 반복을 검토했으니 REVIEW.md를 먼저 읽으라"는 문장 하나가 프롬프트에 붙습니다. `.ralph-done`은 빌더만 만들 수 있습니다.
2. **검증자**: 새 세션에서 검증용 프롬프트를 받습니다. 서버를 띄워 공식 Hurl 테스트를 직접 실행하고, `REVIEW.md`에 판정(PASS/FAIL), 실패 항목, 원인, 수정할 목록을 적습니다. 다른 파일은 고치지 않습니다.
3. **채점**: 원 리포트와 같은 기준의 채점기가 완주 여부를 판정합니다.

### 격리와 자격 증명 [사실]

- 에이전트 세션과 채점은 실행할 때마다 별도 Docker 컨테이너에서 돕니다. 이미지는 Amazon Linux 2023, Node 22.23.3, pi 0.87.1, hurl 8.0.1로 구성했습니다.
- 컨테이너 하나는 메모리 8 GB, CPU 4개, 프로세스 4,096개로 제한했고, 해당 run의 저장소, 세션 기록, 홈 디렉터리만 연결했습니다.
- 컨테이너에는 AWS 액세스 키를 넘기지 않았습니다. Bedrock 호출에만 쓸 수 있고 최대 1시간 뒤 만료되는 Bedrock 단기 API 키만 넘겼으며, 10분마다 새로 발급했습니다.

### 안전장치와 실행 방식 [사실]

- run당 반복 상한은 30회, run 시간 상한은 1,200초, 멈춤 감지는 300초입니다.
- 비용 한도는 run당 $100, 모델당 $500, 전체 $7,000으로 두었습니다.
- 13개 모델은 최대 7개 모델을 동시에 실행했고, 한 모델의 5회 실행은 차례로 진행했습니다. Claude Fable 5.1은 다른 모델이 모두 끝난 뒤 단독으로 실행했습니다.
- 프롬프트는 영어만 사용했습니다.

### 지표 정의

- **완주**: 공식 채점을 통과한 run입니다. 중앙값과 최소·최대는 완주한 run만으로 계산합니다.
- **토큰** [사실]: Bedrock이 응답마다 보고한 사용량을 빌더와 검증자의 모든 요청에 걸쳐 더한 값입니다. 입력은 캐시가 적용되지 않은 입력 토큰이고, 출력에는 추론(reasoning) 토큰이 포함됩니다. 캐시 읽기와 캐시 쓰기는 따로 셉니다.
- **비용** [계산]: 토큰 수에 아래 "적용 단가"의 단가를 곱한 값입니다. 캐시 쓰기는 5분 캐시 단가로 계산했습니다. pi가 캐시 유지 시간을 지정하지 않으며, 이때 Bedrock 기본값이 5분이기 때문입니다.
- **랄프 반복**: 빌더가 실행된 반복 횟수입니다. 원 리포트의 반복 횟수와 같은 정의입니다.
- **LLM 요청**: 모델이 돌려준 응답 수입니다. 모델 수준의 "턴"에 해당하며 빌더와 검증자를 합친 값입니다.
- **run 시간**: run 시작부터 끝까지의 시간이며, 빌더·검증자 세션과 채점 시간을 포함합니다. 원 리포트의 소요 시간은 에이전트 세션 시간이라 정의가 다릅니다.

## 한계와 해석 주의

1. **과제는 하나이고, 실행은 모델당 5번입니다.** 순위는 이 과제와 이 구성에서 관측한 결과입니다. 같은 모델에서도 가장 비싼 run이 가장 싼 run의 최대 약 2.7배(GPT-6 Luna)였습니다.
2. **원 리포트와 구성이 다릅니다.** 원 리포트는 모델마다 다른 하네스(Claude Code, Codex CLI, pi 등)로 에이전트 하나를 실행했습니다. 이번에는 모든 모델을 pi와 Bedrock Converse에서 빌더+검증자 2-에이전트로 실행했으므로, 검증자 몫만큼 토큰과 비용이 늘어납니다. 하네스 간 비교가 아니라 같은 하네스 안에서의 모델 비교입니다.
3. **1차 실행을 폐기했습니다.** 처음에는 에이전트를 컨테이너 없이 한 호스트에서 7개까지 동시에 실행했습니다. 세션 기록을 보니 에이전트들이 `pkill -f`, `fuser -k`처럼 호스트 전체를 대상으로 하는 명령을 실행해, 다른 run의 서버나 채점 서버를 멈출 수 있었습니다. 결과가 오염됐을 가능성을 배제할 수 없어 집계에서 빼고, 격리 컨테이너로 다시 실행했습니다. 원 리포트는 run을 하나씩 실행하므로 이 문제가 없습니다.
4. **검증자가 서버 포트를 원래 기준보다 엄격하게 봤습니다.** 검증자 프롬프트는 서버를 `PORT` 환경 변수의 포트로 띄우라고 요구하지만, 원래 완주 기준에는 이 요구가 없습니다. 공식 채점은 서버가 실제로 연 포트를 찾아 테스트하므로, 이 차이는 REVIEW.md의 내용만 바꾸고 완주 판정에는 영향을 주지 않습니다.
5. **에이전트가 자기 프로세스를 종료한 세션이 있습니다(exit 143).** pi는 프롬프트 전체를 명령줄 인자로 받습니다(원 리포트도 같습니다). 그래서 에이전트가 프롬프트 안의 문구로 `pkill -f`를 실행하거나 node 프로세스를 모두 종료하면 자기 자신도 종료됩니다. 검증자 쪽 노출은 이 보고서의 검증자 프롬프트에 `npm run dev` 같은 문구가 들어 있어 생겼습니다. 이미 끝난 run과 비교할 수 있도록 실행 도중에 프롬프트를 바꾸지 않았습니다.
6. **검증자의 효과는 판단할 수 없습니다.** 검증자 없는 비교군이 없고, 대부분 첫 반복에 완주해 빌더가 REVIEW.md를 실제로 읽은 run이 적습니다.
7. **그룹 2는 모델이 2개입니다.** GLM 5.3은 원 리포트에 없는 모델이라, 공개 기준값은 glm-5.3-flash의 토큰을 빌린 [추정]입니다.
8. **Kimi K3의 캐시 동작이 모델 카드 설명과 달랐습니다.** 모델 카드는 명시적 프롬프트 캐싱을 Converse가 아닌 API에서만 제공한다고 적고 있지만, Converse 호출에서도 Bedrock이 캐시 읽기·쓰기 토큰을 보고했습니다. 보고된 그대로 계산했고, 어떤 방식으로 캐시가 적용됐는지는 확인하지 못했습니다(확인 불가).
9. **실행 시점과 동시성이 다릅니다.** Claude Fable 5.1은 다른 13개 모델의 실행이 끝나고 약 4시간 18분 뒤에 단독으로 실행했습니다. Bedrock 쪽 부하와 호스트 동시 실행 수가 달랐을 수 있으며, 이것이 run 시간에 준 영향은 측정하지 않았습니다. 토큰과 비용은 실행 시점의 영향을 덜 받는다고 보지만 검증하지 않았습니다 [추정].
10. **비용은 계산값입니다.** 2026-10-12 단가 기준이며, 단가가 바뀌면 결과도 달라집니다.

- **run별 수치**: 위 "모델별 결과" 차트에서 모델 행을 펼치면 5회 각각의 값이 나옵니다. 같은 값이 이 저장소의 `src/data/ralph-loop-bedrock.json`(`runs` 항목)에 있습니다.
- **하네스 스크립트와 원 데이터**(세션 기록, run별 지표 CSV, 집계 파일)는 이 저장소에 포함하지 않았습니다. 하네스의 기본 구조는 [원 저장소](https://github.com/roboco-io/coding-agent-benchmark)에 있습니다.
